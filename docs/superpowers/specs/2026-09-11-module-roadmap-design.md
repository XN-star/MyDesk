# MyDesk 模块候选清单与路线图（v1.2 之后）

日期：2026-09-11
依据：当前 MyDesk v1.2.0 的 12 个模块、用户场景调研、桌面端（Tauri 2）原生能力盘点、与同类开源项目（思源、Logseq、AppFlowy、uhabits、Super Productivity、Glance、Things 3、TickTick、Notion Calendar、Reflect、Day One）的能力差距分析。

## 0. 定位不变

- **本地单机、无账号、SQLite、100% 数据本地**——所有候选必须服务这个定位。
- **桌面优先**（Tauri 2 + Windows）——能用桌面原生能力（剪贴板、全局快捷键、系统托盘、麦克风、文件系统）是天然的差异化壁垒，应优先挖掘。
- **轻量、个人、不联网**——AI 类能力（云端大模型、语音转写云 API）需要明确"用户主动授权 + 本地缓存明文"或"完全本地小模型"才纳入。

排除项：云同步 / 账号体系 / 团队协作 / 插件市场（与定位冲突，暂不考虑）。

## 3. 推荐落点（Top 5 + 理由）

按"用户感知最强 + 复用现有数据最多 + 桌面端能力用满"挑出 Top 5：

### ① 睡眠记录（G1）
- **理由**：与「轻盈计划」并成完整的"健康三件套"（体重/运动/睡眠），数据联动 BMI 与周回顾；复用 habit_logs 表与提醒引擎，工程量极小。
- **核心交互**：每晚"睡觉"打卡 + 早起"醒了"打卡，自动算时长；早晨弹出"昨晚睡了 X 小时"；可加 1-5 质量评分与文字心情。
- **风险**：低。需注意时区与跨夜计算。

### ② 周回顾自动生成（G2）
- **理由**：这是"MyDesk 作为工作台"真正区别于"记账 App + 任务 App"的关键能力——把已有的六类数据（任务/专注/记账/习惯/锻炼/体重/可选睡眠）每周自动生成一篇可编辑的回顾，落到速记或日记。**形成回顾闭环**。
- **核心交互**：每周日晚 20:00 弹通知 + 概览卡片"本周回顾" → 一键生成 Markdown → 在速记里编辑。
- **风险**：中。要先定义"完成"的口径（与 v1.2 速览"今日任务"修复是同源问题）。

### ③ 剪藏板 / Web Clipper（I1）
- **理由**：Tauri 桌面端最容易拉开"网页版笔记"差距的能力。选中文字或截图一键落到"灵感速记"，配 `[[]]` 自动加双向链接。
- **核心交互**：注册全局快捷键（如 `Alt+Shift+C`）→ 截取当前选中文字 / 截图 → 弹小窗预览 + 选目标速记 → 自动保存。
- **风险**：中。需要 Tauri 的 clipboard / screenshot 权限；Windows 11 已默认放开。

### ④ OKR / 目标（G5）
- **理由**：让任务和习惯有"为什么"。用户留存的根本动力。
- **核心交互**：建"目标"（季度）+ 子目标（KR）→ 任务/习惯可挂到某个 KR 下 → 目标页看完成度（按子目标聚合）。
- **风险**：中。涉及任务表加列、迁移、概览卡扩展。

### ⑤ 心情日记 / 与速记合并（G3）
- **理由**：与速记合并（kind='diary'）成本极低；价值密度大（情绪是健康、回顾的输入）。
- **核心交互**：今日速记顶部固定"今日心情"1-5 量表 + 备注；速记列表可按心情筛选与统计。
- **风险**：低。需明确"日记"和"普通速记"的边界（前者按日聚合，后者自由）。

## 4. 暂不推荐 / 推迟

- **密码管理**（L3）：安全敏感，与"个人工作台"定位错位，建议拆出独立项目；折中方案：在速记里支持"加密块"（用户输入密码解开）。
- **AI 类**（I3 语音云 API、I4 OCR 云 API、所有"AI 总结周回顾"）：违反"数据本地"原则，引入前必须先做"完全本地小模型"或"用户主动授权 + 数据离开前明示 + 本地保留原文"两种模式。
- **云同步**（C1/C2）：定位冲突；如未来要做，应作为"可选插件"挂载，不进核心。
- **多账本**（L5）：等记账模块月活/粘性指标出来后再决策。
- **时间块**（E4）：与现有"任务+月历"重叠度高，先观察用户对"截止日期 vs 时段"的反馈。

## 5. 推进顺序建议

```
v1.3  心情日记（最薄、G3）→ 模板（E1）   ← 一次迭代
v1.4  睡眠记录（G1）→ 饮水打卡（H2）      ← 健康补全
v1.5  周回顾自动生成（G2）                ← 回顾闭环
v1.6  剪藏板 / Web Clipper（I1）          ← 桌面差异化
v2.0  OKR / 目标（G5）→ 时间块（E4）       ← 平台化（前置：周回顾粘性）
```

> 顺序原则：低风险高价值先行；形成"日记 → 回顾 → 目标"的纵向价值链；桌面原生能力（剪藏）做差异化锚点。

## 6. 与定位的边界检查

每加一个模块都过这道关：
- [ ] 数据 100% 留在本地？无例外时一律不通过。
- [ ] 不引入账号体系？
- [ ] 复用现有数据越多越好（避免"模块孤岛"）？
- [ ] 能用桌面原生能力加分？
- [ ] 不与现有模块重叠超过 50%？

若任一项不过，挪到 "暂不推荐"。
