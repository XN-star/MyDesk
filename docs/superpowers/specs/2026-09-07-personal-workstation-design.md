# 个人工作台软件 · 设计文档

- 日期：2026-09-07
- 状态：待用户审阅
- 需求收集方式：聊天问答逐项确认（见「需求决定记录」）

## 1. 项目概述

一款 Windows 桌面个人工作台软件。MVP 提供「任务看板」与「日历日程」两个模块；整体架构采用**模块注册表**机制，使未来的笔记、快捷入口、信息小部件等模块能够以「新建目录 + 注册一行」的方式加入，并可在界面中开关。

**成功标准**：

- 用户可创建、拖拽、编辑、删除任务；日历可查看与增改某天的日程与到期任务。
- 任务到期时收到 Windows 系统通知。
- 全局快捷键可随时唤起快速面板记录任务。
- 数据 100% 存本地，可手动导出/导入 JSON 备份且往返一致。
- 新增一个模块不需要修改注册表之外的既有代码。

## 2. 需求决定记录（问答确认结果）

| 维度 | 决定 |
|------|------|
| 核心定位 | 全能模块化工作台（模块可开关，类似 Notion 的自由度） |
| 运行形态 | Windows 桌面应用，技术栈 Tauri |
| MVP 模块 | 任务看板（三列拖拽）+ 日历日程（月历 + 当日详情） |
| 数据存储 | 纯本地 SQLite + 手动导出/导入 JSON 备份 |
| 外观主题 | 三档：跟随系统（默认）/ 浅色 / 深色，设置页可切换 |
| 到期提醒 | Windows 系统通知，应用后台运行也能收到 |
| 快捷操作 | 全局 Alt+Space 快速面板，含简单自然语言日期解析 |
| 看板数量 | MVP 单看板，数据结构预留 board_id 多看板字段 |
| 界面语言 | 纯中文 |

**明确不做（YAGNI）**：云同步、账号体系、多看板 UI（仅预留字段）、看板+列表双视图、时间轴日历视图、中英双语 i18n、通知自定义提前量、复杂自然语言解析。

## 3. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面壳 | Tauri 2.x | 安装包小、内存占用低，前端仍用 Web 技术 |
| 前端框架 | React 18 + TypeScript | 生态成熟，拖拽/日历现成库多，长期扩展成本最低 |
| 状态管理 | Zustand | 轻量，适合模块化的分 store 设计 |
| 拖拽 | dnd-kit | 跨列拖拽与列内排序支持好，无障碍友好 |
| 日期 | date-fns | 函数式、按需引入 |
| 存储 | rusqlite（SQLite） | 单文件本地库，成熟稳定 |
| 通知 | tauri-plugin-notification | Tauri 官方系统通知插件 |
| 测试 | Vitest（前端）+ Rust 内建 test（后端） | 各自生态默认选择 |

## 4. 总体架构

```
┌─────────────────────────────────────────────┐
│                 主窗口 (React)               │
│  ┌──────┐  ┌────────────────────────────┐  │
│  │ 侧边栏 │  │      模块内容区（路由）      │  │
│  │ 动态   │  │  只显示「已启用」的模块页面  │  │
│  │ 图标   │  └────────────────────────────┘  │
│  └──────┘   ┌──────────────────────────┐    │
│             │ 快速面板 (Alt+Space 弹出)  │    │
└─────────────┴──────────────────────────┴────┘
         ↕ Tauri IPC (invoke)
┌─────────────────────────────────────────────┐
│        Rust 后端：SQLite + 通知 + 备份        │
└─────────────────────────────────────────────┘
```

- 前端不直接访问数据库，所有数据操作通过 Tauri command（如 `task_create`、`task_move`、`events_by_date`、`settings_get`、`settings_set`、`backup_export`、`backup_import`）。
- Rust 端职责：SQLite 读写、备份导入导出、到期提醒的扫描与定时、全局快捷键注册（tauri-plugin-global-shortcut）。

## 5. 模块化机制（核心设计）

每个模块是一个自包含目录 `src/features/<模块名>/`，实现统一接口：

```ts
interface Module {
  id: string;            // 如 "tasks" / "calendar"
  name: string;          // 中文名，如 "任务看板"
  icon: string;          // 侧边栏图标标识
  defaultEnabled: boolean;
  route: string;         // 页面路由，如 "/tasks"
  component: React.FC;   // 模块主页面
  settingsSchema?: ...;  // 可选：模块自己的设置项
}
```

- 所有模块在 `src/modules/registry.ts` 注册；侧边栏与路由**只从注册表读取**。
- 模块启用状态存在设置表（key=`enabledModules`，value=JSON 数组），设置页「模块管理」可视化开关，改动即时反映到侧边栏与路由。
- 新增模块流程：新建 `src/features/<name>/`（实现 `Module` 接口）→ `registry.ts` 加一行。不改动任何既有模块代码。
- MVP 注册两个模块：`tasks`（任务看板）、`calendar`（日历）。

## 6. 数据模型与存储层

> 2026-09-08 修订：看板与日历**统一为一种条目**——原独立的 `events` 表已废除（v1→v2 迁移把日程并入任务：`due_at = date + time_start`，无时刻的日程落在当天 09:00）。日历上的一切条目都是任务，天然双向同步；到点自动弹提醒。

- 数据库文件：`%APPDATA%/personal-workstation/app.db`；首次启动自动建表（直接为 v2 形态）；`user_version` 管理迁移（v1 旧库自动升级）。
- 日期时间格式：`due_at`/`created_at` 等用本地无时区 ISO：`YYYY-MM-DDTHH:MM:SS`，可直接字符串比较。

```sql
-- v2：任务 + 设置两张表
CREATE TABLE tasks (
  id          TEXT PRIMARY KEY,   -- UUID
  board_id    TEXT NOT NULL DEFAULT 'default',  -- 预留：多看板
  title       TEXT NOT NULL,
  description TEXT DEFAULT '',
  status      TEXT NOT NULL DEFAULT 'todo',     -- todo | doing | done
  priority    INTEGER NOT NULL DEFAULT 1,       -- 0=低 1=中 2=高 3=紧急
  due_at      TEXT,               -- YYYY-MM-DDTHH:MM:SS，可空=无时刻
  sort_order  REAL NOT NULL,      -- 列内排序（拖拽时用）
  done_at     TEXT,               -- 完成时间
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL              -- JSON 字符串
);
```

**要点**：

- 看板与日历同源：日历某天详情 = 按 `due_at` 日期筛选的任务，纯时间顺序；看板与日历任意一侧增改即时互通。
- 无 `due_at` 的任务不出现在日历（没有日期概念），只在看板显示。
- `board_id` 恒为 `'default'`，多看板上线时无需改表。
- **备份**：v2 格式（`tasks` + `settings` + `version: 2`）；导入兼容 v1（其中的 `events` 逐条转换为任务）与 v2；版本高于当前拒绝；校验失败**零写入**（事务内整库替换）。
- 导出/导入通过系统文件对话框选择位置。

## 7. 界面与交互

**主窗口**：默认约 1200×800，最小 900×600。

```
┌────────┬──────────────────────────────┐
│ ◆ 个人工作台 │  今日摘要条：N 个未完成任务 · 今日 M 项 · 下个截止 Xh 后 │
├────────┼──────────────────────────────┤
│ ▦ 任务看板│                              │
│ ▤ 日历   │     模块内容区                │
│         │  （看板 / 日历 / 设置页）       │
│ ⚙ 设置   │                              │
└────────┴──────────────────────────────┘
```

**侧边栏品牌头**（2026-09-08 修订）：顶部为「◆ 个人工作台」品牌块——36px accent 色圆角图标底 + 18px 加粗名称，加大留白下移。（窗口最顶部的系统标题栏由 Windows 绘制，应用内不修改。）

**任务看板页**：

- 三列：待办 → 进行中 → 已完成；卡片显示标题、优先级色点、截止日期（过期标红）。
- dnd-kit 实现跨列拖拽换状态、列内拖拽排序（写 `sort_order`）。
- 点击卡片打开右侧抽屉编辑：标题、描述、优先级、截止日期、删除。
- 列顶「+」快速新建；拖入「已完成」自动记录 `done_at`，拖回则清除。

**日历页**（2026-09-08 修订：与看板同源，无独立日程）：

- 月历格子；有任务的日期显示优先级色圆点（上限 6 个，超出显示 "+N"）。
- 点击日期 → 右侧当日详情面板：该日条目按时刻排序，可勾选完成、删除；添加表单 = 标题 +「时刻」滚轮（明确标注用途：到点弹提醒、按此排序），默认 09:00。

**时间与日期输入**（2026-09-08 新增）：不使用系统原生 `datetime-local`。日期 = 应用内月历弹层选择（可清除）；时间 = 时/分双列滚轮（▲▼ 按钮 + 滚轮 + 点选）；带明确标签说明时间用途。

**快速面板**（全局 Alt+Space）：

- 屏幕居中小窗：输入即搜任务/事件，结果列表上下键可选、回车打开选中项；若无匹配结果（或按特定前缀如无匹配直接回车），则将整行输入文本新建为任务。
- 支持简单自然语言日期短语：`今天/明天/后天/周X/HH:MM`（如「明天 15:00 开周会」），解析出的日期写入任务 `due_at`，其余文本为标题；MVP 只做规则匹配，不引入模型。

**设置页**：

- 模块管理（开关各模块）、备份导出/导入、主题三档（跟随系统[默认]/浅色/深色）、关于。

**主题**：CSS 变量双套色板；`跟随系统` 档读取 Windows 深浅色并监听系统变化自动切换；选择持久化在设置表。

## 8. 提醒机制

- 应用启动及每次任务变更后，Rust 端扫描未来 `due_at`，计算最近一个到期点，用定时器在到期时刻触发系统通知（标题=任务名，点击唤起主窗口）。
- 每天一次兜底扫描，覆盖跨天计算窗口。
- 同一任务只提醒一次（内存记录已提醒 id）。
- MVP 提前量固定为到期时刻本身，不做自定义提前量。
- Windows 通知被系统关闭时，降级为应用内列表页醒目横幅。

## 9. 错误处理

- SQLite 操作失败 → 前端 toast 提示，保留用户已输入内容（不丢数据）。
- 备份导入：版本不匹配或 JSON 损坏 → 明确报错，不执行任何写入。
- 数据库文件损坏 → 启动检测到时提示用户，允许导出仅存数据，然后自动重建空库。
- 通知不可用 → 应用内横幅降级（见第 8 节）。

## 10. 测试策略

- **前端单测（Vitest）**：自然语言日期解析规则、任务状态流转（含 done_at 写入/清除）；组件测试覆盖看板拖拽后状态变化、日历当日详情合并展示。
- **Rust 集成测试**：tasks/events/settings CRUD；备份导出→导入往返一致性；损坏 JSON 拒绝导入。
- **手动验收清单**：拖拽换列、通知弹出、备份往返数据一致、主题三档切换、Alt+Space 唤起、模块开关后侧边栏即时变化。

## 11. 边界与未来扩展

- 多看板：`board_id` 已预留，UI 与创建/切换流程留给后续版本。
- 新模块（笔记、快捷入口、信息小部件）：按第 5 节流程接入，不需要改注册表以外的代码。
- 数据迁移：表结构加列时通过版本迁移执行，备份 JSON 携带 `version` 以便跨版本导入时转换。
